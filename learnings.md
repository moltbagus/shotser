# ShotEye Learnings

## 2026-08-19

- A visible macOS window is not proof of interactivity; `NSRunningApplication.isActive` must be checked.
- Activating only from a manually-created `NSWindow` can race app launch. Use an `NSApplicationDelegate` launch hook plus post-mount activation.
- Full-screen capture overlays must disable mouse events and close, not only order out, before presenting the editor.
- GitNexus is useful for tracing `ShotserApp -> CaptureModel -> EditorView -> ToolbarIconButton` control flow.
- WSL2 server sync cannot be assumed; verify SSH reachability before claiming cross-machine synchronization.
- A local app launch and a fresh extracted ZIP can differ; evaluate the distributed artifact, not only `dist/Shotser.app`.
- `NSRunningApplication.isActive` can remain false after `open -n`; repeated activation on launch and `applicationDidBecomeActive` closed the packaged-app gap.
- A raw Tauri development executable is not reliably discoverable by desktop automation; test the signed/bundled `.app` with a unique bundle identifier instead.
- Tauri bundles frontend assets inside the application binary/package, so absence of `Resources/dist` is not evidence of a missing `frontendDist` payload.
- A clickable toolbar must be tested end-to-end: accessibility discovery plus an observable WebKit-to-Rust status response is a useful deterministic seam.
- Tauri's default local bundle may leave only the executable ad-hoc signed; set `bundle.macOS.signingIdentity` to `"-"` to produce a strict-verifiable local package on Apple Silicon. This is not a substitute for Developer ID signing and notarization.
- Stale `tauri dev`, Vite, and debug binaries can remain after an interrupted build and make the user appear to have multiple broken apps; clean those exact project processes before evaluating the packaged bundle.
- Capture temp files are mutable process state: delete previous output before launching `screencapture`, and validate the PNG signature before preview/export so cancellation cannot masquerade as an old successful capture.
- Native capture is modal from the user's perspective; disable competing editor actions until the Rust capture command returns so a second invocation cannot create overlapping selectors.
- On-call debugging standard: do not accept a plausible story without evidence; check timing, correlated symptoms, recent configuration/deployment changes, and signals that rule out alternative causes before declaring a fix.
- Interactive desktop capture must hide the editor before invoking the native selector and restore/focus it from an unconditional cleanup path; otherwise the app obscures selected pixels or remains hidden after Escape.
- On macOS, reserve common system screenshot chords; `⌘⇧Y` is used as Shotser's non-reserved default and emits one frontend capture request only on key press.
- Capture export state should be Rust-owned, not inferred from a shared temp file; temp files are adapter artifacts and must not be the product's source of truth.
- Tauri's frontend window APIs have a separate capability ACL from Rust-side `WebviewWindow` APIs. A `finally` restoration can compile but still fail at runtime unless `allow-hide`, `allow-show`, and `allow-set-focus` are granted to the main window.
- The macOS category name “Screen & System Audio Recording” is the TCC gate for display capture; Shotser's PNG-only `screencapture` invocation does not request audio. An ad-hoc build has no stable Team ID, so TCC cannot retain screen-capture permission across rebuilt identities.
- The UI harness must exercise the packaged native selector lifecycle. It uncovered the missing `window|show` ACL that unit tests, Rust checks, and a healthy process all missed.
- A persistent locally self-signed code-signing certificate is not a safe stand-in for Apple Developer ID signing here: the certificate-signed ShotEye app passed `codesign --strict` but its WebKit editor rendered blank, while the restored ad-hoc control displayed every toolbar action.
- macOS `screencapture -i` operates in interactive desktop selection mode; `-m` is the flag that would restrict it to the main monitor. Explicitly select `-J selection` and test that no `-m` or `-D` argument is introduced, while retaining a physical secondary-display drag as the only end-to-end proof.
- For user-configurable global shortcuts, register the candidate before unregistering the active key. This preserves a working capture path when the replacement conflicts or fails parsing, and keeps shortcut behavior available before the frontend finishes loading.
- Separate permission actions by consequence: a consent request and a System Settings deep-link are different recovery paths, and naming both directly keeps screen-capture failures actionable without surprising the user.
- A native macOS titlebar and an HTML imitation titlebar must never coexist. Use the native close/minimize/zoom controls as the only window authority, and inspect the packaged app—not just DOM/CSS—for duplicate chrome.
- Crop operations should normalize a two-point drag once in image coordinates, then reuse those bounds for the preview guide and canvas export. Test reverse and off-image drags so `drawImage` never receives negative or out-of-range geometry.
- Treat macOS Screen Recording as an exact-binary acceptance dependency. A newly installed ad-hoc build must preflight and report a single recoverable state; testing the native selector itself requires an action-time-approved TCC grant.
- Annotation history needs a dedicated state model, not independent button callbacks. Keep append, Undo, Redo, and Clear transitions deterministic so React state and enabled controls cannot drift apart.
- Keep platform-neutral shortcut registration syntax at the native boundary, but translate it before it reaches the product UI. Users should see `⌘⇧Y`, not `CommandOrControl+Shift+Y`.
- Selection hit testing belongs in source-image coordinates and should iterate annotations from newest to oldest so overlapping marks select the visible topmost mark.
- Pointer-driven editing drafts need a synchronous ref alongside React state when pointerdown can be followed immediately by pointermove/up. Keep the original annotation in the draft and derive every preview/final position from the pointer-down origin to prevent double translation.
- When repository metadata is intentionally kept outside `.git`, renaming the workspace also requires renaming the isolated Git directory, updating `core.worktree`, and refreshing local tooling names; the remote URL can remain unchanged unless a remote rename is explicitly requested.
- Annotating in source-image coordinates and flattening only at Copy/Save preserves a lossless preview and makes zoom independent from exported geometry.
- Decode all external image inputs into a canonical RGBA PNG at the Rust boundary. This avoids format-specific behavior in the React editor and makes copied, saved, opened, and pasted images use one model.
- Clipboard import should request PNG first and TIFF second on macOS; both are common native image representations and are more reliable than assuming a text-oriented clipboard command can access image bytes.
- Resize handles should be rendered from the selected annotation's source-image geometry, while the drag draft keeps an immutable pointer-down snapshot. Use the SVG root from `ownerSVGElement` for handle pointer events so child circles map back into the same image coordinate system as annotation drags.
- Tauri preserves a configured resource directory in the packaged bundle. When a helper is configured as `native/ShotEyeSelector`, resolve it from `resource_dir/native/ShotEyeSelector` at runtime and keep a flat-path fallback for alternate layouts; packaging alone is not proof that the executable can be found.
- Editor shortcuts should be mapped through a pure action function and ignored for editable targets or while shortcut recording is armed. This keeps keyboard behavior testable without coupling it to React state and avoids stealing text-entry chords.
- A borderless AppKit panel does not reliably receive Escape until it explicitly overrides `canBecomeKey`; deactivation must also close the selector so a failed capture cannot strand an overlay.
- Capture a selected display region only after ordering the selector panel out and yielding to the main run loop; otherwise the dimming overlay can contaminate the pixels returned by Core Graphics.
- Core Graphics bitmap contexts use a lower-left origin. A top-left logical transform is required when composing screenshots from monitors above or below the primary display.
- Preserve the last valid canonical capture until a new capture has validated successfully. React may keep showing an old preview after a native failure, so clearing backend state first creates a hidden Copy/Save regression.
- Native helper exit codes are part of the IPC contract. Keep cancellation, permission failure, and execution failure distinct so fallback behavior cannot create a second selector or hide a real error.
- Include `NSScreenCaptureUsageDescription` in the packaged plist and align `LSMinimumSystemVersion` with native helper APIs; a strict signature alone does not prove a permission-ready package.
- A selector that orders itself out before capture must distinguish “selection has committed” from “the app lost activation”; otherwise AppKit can cancel the valid handoff before the pixel read. Native temp output also needs an RAII cleanup guard because IPC and process failures can return early.
- macOS `screencapture` already provides a native window-selection mode via `-i -J window`; adding it as a first-class `CaptureMode` keeps permission, repeat, validation, and export behavior consistent without teaching the area selector to model window hit-testing.
- A permission fix is easier to operate when the product reports the non-prompting preflight at launch; users can distinguish “not granted to this exact build” from a capture-action failure before invoking a selector.
- Always-on-top is a window capability, not a CSS layering trick; call the native Tauri API and update the button only after the OS confirms the transition so the UI cannot drift from window state.
- Clipboard integrations often need a temporary file for AppleScript, but a fixed shared `/tmp` filename creates a race and symlink surface; reuse the private directory/RAII pattern at every native file boundary.
- Keep the editor's canonical image format stable and choose Save encoding from the user's explicit extension; this gives flexible exports without multiplying preview, clipboard, and annotation-state representations.
- A third-party drag-out plugin is not automatically a safe integration: inspect its command namespace, default feature behavior, and actual promise callback before adopting it. An archive-oriented plugin with a no-op default extractor is not a general PNG export path.
- AppKit drag sessions must be created on the macOS main thread from a live pointer event and an active editor window. If the native bridge cannot access `NSApp.currentEvent`, return a visible recovery message instead of claiming a drag started.
- Finder drag-out needs file lifetime ownership distinct from short-lived clipboard staging. Keep the staged file in a private managed location until app shutdown or an observed drag completion; deleting it immediately after IPC returns races Finder's drop.
- A Tauri IPC call does not preserve the originating AppKit event. For drag initiation, synthesize a fresh mouse-down event on the macOS main thread from the current pointer location and provide a real drag image; otherwise AppKit can reject or render an empty drag.
- Export preparation is shared mutable native state. Queue background Drag refreshes behind Copy/Save and gate readiness by a capture/annotation revision so an older render cannot overwrite the latest annotated PNG.
- A repository can recreate an app bug through its tooling even when the current binary is correct. Make the supported product the only root packaging/run path and isolate legacy implementations so users cannot accidentally launch a second app.
- Startup readiness flags and pending event flags must share one lock (or one atomic state machine); separate mutexes allow a request to arrive between readiness publication and pending-event consumption.
- A multi-display screenshot is invalid if any intersecting display read fails. Requiring only one surviving image silently produces transparent holes that pass ordinary PNG validation.
- Architecture-specific package names must be backed by an explicit target and binary inspection; printing an arm64 DMG path from a host-default build can ship a misleading artifact.
- Process smoke checks must match the executable field exactly (or an anchored product suffix), not search the entire `ps` row; otherwise the shell/awk command can report a duplicate process or hide a single-instance handoff.
- Diagnostic IPC acknowledgements are unsafe in a user-facing editor when they share the status channel with capture and permission results; keep tool selection local or use a dedicated command whose response cannot overwrite product status.
- Renaming a bundled executable requires a clean bundle replacement: in-place copy can retain the old binary, and Launch Services may continue starting it. Move the exact prior app to Trash, copy the new bundle, and verify both `CFBundleExecutable` and the live process path.
- Public packaging must fail closed: local ad-hoc/self-signed identities are useful for evaluation but cannot satisfy Developer ID, Gatekeeper, or notarization requirements. Validate the exact identity before invoking the release build.
- Shared desktop toolbar controls need both pointer and keyboard affordances: keep hover styling separate, use a stable minimum hit target, and never suppress `:focus-visible` without replacing it with an equally clear indicator.
- Unicode symbols are not stable product iconography across WebKit/font environments. Keep icons decorative, bundle the shape in the UI, and preserve a visible text label plus an accessible name for every action.
- Clipboard helpers are native operations too: AppleScript `.status()` can hang just like a capture helper. Use one owned timeout/kill/reap boundary for every external child and keep timeout messaging separate from ordinary command failure.
- A Save dialog is part of the async export transaction: if rendering happens before path selection, the user can edit the image while choosing a destination and receive a stale file. Resolve the destination first, then prepare and commit the latest stable revision.
- An ignored build directory can still contain a launchable legacy app. Treat product layout as a release invariant: archive stale bundles recoverably and make package/verification fail closed when a competing `.app` appears in the supported build root.
- A layout guard needs a negative test as well as an empty-directory check. A temporary dummy bundle verified that both package and verification paths stop before launch, proving the duplicate-product invariant is enforced rather than merely documented.
- A parent Screen Recording grant does not automatically prove that a bundled helper has the same TCC access. Add a non-prompting helper probe before showing an overlay; on the reserved denial result, choose the system selector fallback without opening a second consent path.
- Treat a bundled selector as an optimization, not a hard dependency: platform-specific process-spawn failures can surface as `ErrorKind::Other`, so every helper exec failure should reach the tested system-selector fallback.
- Persisted global shortcuts can become invalid after another app claims the key or after a permissions/configuration change. Recover only at startup by clearing the rejected preference and showing the known active default; preserve the active shortcut when a user explicitly tries a conflicting replacement.
- Async export preparation must not trust a React closure captured before a user annotation finishes. Read the latest image state through refs, attach a monotonic capture/annotation revision to the preparation, retry when it changes, and bound instability so Copy, Save, and Drag cannot silently publish an older PNG.
- Release evidence should be executable and path-specific. A shared installed-package verifier prevents a hand-written smoke command from silently checking a different bundle, architecture, helper, or process than the artifact the user will launch.
- Revision freshness prevents stale payloads, but it does not prevent two native export operations from overlapping. Put Copy, Save, and Drag behind one async guard and release it in `finally`, including a cancelled Save dialog and native failure.
- Separate capture and export locks still permit native adapter overlap. Use one operation lane for every action that hides the editor, mutates canonical native state, or starts a native clipboard/file operation; acquire it before the first await.
- Native menu callbacks can outlive the React render that created them. Route menu actions through synchronous current refs so a menu-triggered Copy/Save/capture sees the latest canonical editor state and shares the same concurrency guard as toolbar and keyboard actions.
- A display union's bounding rectangle can contain physical gaps. Validate coverage slab-by-slab before compositing, and treat inconclusive helper permission probes as fallback conditions rather than permission to launch an unusable overlay.
- Blocking on a native selector with `Child::status()` turns a hung helper into a hung UI. Own the child, poll it with a bounded deadline, kill/reap on timeout, and treat timeout as a terminal capture failure rather than starting another overlay.
- A helper permission probe is part of the interactive capture critical path; calling `status()` there can hide the editor before the capture timeout begins. Use the same short owned-child timeout and treat timeout as an inconclusive fallback.
- Background export prewarming must never write shared native image state. Cache revision-tagged rendered bytes locally and publish them only inside the user-triggered exclusive export lane, otherwise a delayed render can replace a newer native capture.
- macOS DMG cosmetic AppleScript is an optional presentation step, not a packaging dependency. In automation or Finder-restricted sessions it can hang indefinitely; direct `hdiutil` creation keeps the signed app artifact deterministic and testable.
- A nonempty DMG is weak evidence. Mount the exact disk image read-only and re-run bundle identity, architecture, helper, signature, parity, and artifact checks against the embedded app.
- A mixed-DPI compositor test that checks one center pixel can miss a seam shift or transparent edge. Use explicit RGBA/nearest-neighbor output and scan every synthetic output pixel for expected ownership and opaque coverage.
- Compositor self-tests should inject synthetic `CGImage` inputs and avoid `NSScreen`, TCC, or the AppKit run loop; this makes coordinate and scaling regressions runnable in package verification even without a second physical display.
- `CGRect.integral` hides the rounding policy at a display boundary. Use explicit floor-min/ceil-max bounds for both source crops and destination rectangles, then test fractional origins, seam columns, and vertical bands end to end.
- A compositor test can pass while the real display crop is inverted because it injects already-cropped images. Factor the crop transform and test top-row-first full-image data at both display extremes.
- Permission recovery is user-facing native work too: launch System Settings through the same owned-child deadline as capture so a stuck opener cannot strand the editor.
- A global shortcut is not active merely because its value is stored in app state. Track registration separately, treat default startup registration as best-effort, and retry the same value after a conflict without aborting the editor launch.
- A root runner can recreate a macOS permission bug even when the app binary is correct: launching the build-tree bundle while authorizing `/Applications/ShotEye.app` creates different TCC targets. Install one freshly built bundle at the canonical path before launch and verification, and move the prior bundle recoverably instead of overwriting it.
- A non-prompting TCC preflight is necessary but indirect; a packaged helper can pass preflight and still fail at the actual display-read API. Add a noninteractive `CGDisplayCreateImage` smoke gate to the exact installed and mounted-DMG helper, while keeping physical pointer selection as a separate acceptance requirement.
- Permission UX has two independent failure modes: concurrent prompt requests and stale terminal status. Route toolbar and native-menu permission/settings actions through one shared async guard, then capture a status epoch before the native await and commit its result only if that epoch is still current.
- Release tools must bind evidence to the artifact that will be launched: derive the expected DMG path from the target architecture/version, and strict-verify the source bundle before stopping or replacing the canonical installed app.
- The canonical image model has more writers than capture/export: Open, Paste, and Crop can replace Rust-owned bytes too. Put every writer behind the same exclusive native-operation lane, and epoch-check every terminal status so blocked or late work cannot overwrite the user's newest result.
- A `try_wait()?` path is a child-process leak boundary. On any polling error, kill and reap the child before returning so releasing the frontend guard cannot leave a selector or settings process alive.
- Native selector policy is testable without a desktop harness when helper probing, helper execution, and system fallback are injected at the dispatch boundary. Keep those seams narrow and preserve the production process/lifecycle implementation around them.
- S74: macOS's `Screen & System Audio Recording` label does not mean ShotEye requests audio; permission UX should state screen pixels only, while ad-hoc rebuilds must still be treated as new TCC identities until Developer ID signing is available.
- S75: an async crop can outlive the React render that started it. Capture the image/annotation snapshot through synchronous refs, advance an edit revision synchronously for every image or annotation-history mutation, and persist the cropped image only at the guarded export boundary so stale work cannot replace newer state or Rust-owned bytes.
- S76: reducer tests do not prove AppKit event wiring. A permission-free self-test can instantiate the real panel/view, feed synthetic `NSEvent` mouse and Escape events, and assert callback geometry, cancellation cleanup, and responder readiness before physical Accessibility-enabled acceptance.
- S77: a separately executed native helper is part of the distributable trust boundary. Release packaging must validate its Developer ID authority and matching Team ID, not only the outer app's signature; evidence reports should record executable self-test exit codes rather than unconditional prose.
- S78: single-instance focus recovery can be destructive during a hidden capture. Make native capture activity observable to the activation callback and let the capture's RAII guard own the interval; duplicate launches must wait for normal completion restoration instead of revealing the editor mid-selection.
- S79: a strict code-signature pass is not the same as release readiness. Make verification mode explicit and fail closed on missing Developer ID authority, matching app/helper Team IDs, Gatekeeper acceptance, or stapled notarization; preserve local-only evidence for development.
- S80: React event effects can retain an old action closure even when the visible image changes. Include the state that gates the action in the listener lifecycle, while keeping mutable annotation/export state behind synchronous refs to avoid unnecessary rebinds.
- S81: Native menu callbacks are a separate input surface, not automatically equivalent to toolbar handlers. Route every state mutation through one capture-aware dispatcher and make destructive edit commands clear all transient pointer drafts so menus cannot bypass lifecycle invariants.
- S82: A compound async outcome can contain useful data and a recovery error at the same time. Commit the valid payload before surfacing the recovery failure; for startup fallback, retry the supposedly active default and distinguish “displayed” from “registered.”
- S83: Tauri command payload casing is part of the packaged IPC contract. Rust parameters may be snake_case while the default JavaScript bridge expects camelCase; a rejected follow-up command can be swallowed and look like a native capture hang. Add a payload helper/regression and verify the exact bundle end to end.
- S84: A hidden WebView must not be the owner of recovery for a long-running native command. Keep hide/capture/restore in one Rust transaction, run blocking selector work through `spawn_blocking`, and return explicit restoration truth so a second frontend restore cannot mask or stall the real failure.
- S85: Append-only diagnostics need run boundaries. Clear the derived trace before each packaged verifier run and log restore start/complete/failure explicitly; otherwise stale events can make a broken lifecycle look healthy.
- S86: A pure revision predicate is useful but does not make delayed browser work easy to prove. Wrap the actual async crop resolver in a revision-stable helper, return an explicit no-op on invalidation, and test controlled Crop → Reset and Crop → annotation interleavings before packaging.
- S87: When a component-level race matters, project-localize the DOM runtime and mock only native boundaries. Driving the actual Paste → Crop pointer path with deferred `Image` loading exposed test-isolation issues early and proved newer React state survives delayed crop completion; keep physical selector and Accessibility claims separate.
- S88: Capture lifecycle coverage must enter through the real App action, not only a helper or Rust contract. Hold the native promise open to observe the selecting state, trigger re-entry through the current event listener, and test both rejected and explicit cancellation results so the single-flight guard and recovery UI are independently proven.
- S89: Export evidence must follow the user-visible action all the way to the native boundary. Create a real annotation, hold `Image.onload` so canvas preparation is observable, let Save resolve its destination before rasterization, and make Drag tests account for background prewarming without asserting a physical Finder drop.
- Keep hide/action/show/focus orchestration outside the React component so every capture failure path can be tested without Accessibility permission; return action and restore errors separately so the UI preserves its established restore-error precedence.
- Best-effort window restoration should attempt focus independently of show; even a failed show call can leave a focusable window state on some macOS lifecycle paths.
- A successful `screencapture` exit plus valid PNG dimensions proves only the native command boundary; an all-black artifact from the current desktop environment cannot prove that visible pixels or interactive pointer selection work.
- Native selector gesture rules should be pure and shared by drawing and commit paths; otherwise the rectangle shown during a drag can disagree with the rectangle that reaches capture.
- A rejected tiny drag must clear native gesture state; returning early before reset leaves a stale outline and can poison the next mouse-down even when coordinate normalization itself is correct.
- S65: direct writes to a user-selected export path can leave a partial file after an encode or I/O interruption. Encode first, stage beside the destination with `create_new`, sync the complete bytes, and atomically rename; test both replacement and staging cleanup.
- S66: one live process plus a clean launch log is useful packaged evidence, but it does not prove WebView click delivery or native pointer selection. Keep Computer Use/Accessibility availability as an explicit acceptance prerequisite and do not relabel restricted WebContent/XPC noise as a ShotEye defect without a reproducible app-owned failure.
- S67: a public release preflight should fail before any build when the signer or notarization credentials are absent. Preserve a separately labeled ad-hoc evaluation artifact rather than implying it is distributable.

- S90: Tauri's bundle signer can leave an executable resource ad-hoc signed even when the outer app receives a requested identity. For a stable local evaluation lineage, probe private-key access with a bounded standalone `codesign`, sign nested executable resources first, then re-sign the containing app. Keep the result labeled local-only because a self-signed certificate has no TeamIdentifier and cannot prove Gatekeeper or notarization readiness.
- S91: Capture modes can share a native command boundary yet still regress at the user-visible entry point. Extend the real `App` harness across Window, Full screen, and Repeat controls, assert the exact command and valid preview/status, and keep those component results separate from physical selector and permission acceptance.
- S92: Readiness signals are ordering contracts, not merely booleans. When Rust can replay a queued global shortcut, the frontend must not signal ready until its asynchronous event listener is installed. Release artifacts have a similar provenance contract: refresh the canonical DMG from the just-created output atomically and reject parity mismatches before mounting.
- S93: A history feature should attach to the canonical successful-image boundary, not to every attempted action. Recording only validated capture/import results avoids stale or cancelled entries; an immutable bounded session model adds restore value without creating a new persistence/privacy boundary. Restore must clear annotation and crop state before presenting the earlier source image.
- S95: Base64-backed session history needs a payload budget as well as an entry count. Evict oldest entries against an encoded-size cap, and prove that policy with synthetic strings so the regression stays fast and memory-safe.
- S96: Install missing static-analysis components before treating their absence as a code-quality conclusion. Clippy can be made clean with narrow fixes while formatter drift may span unrelated WIP; keep those scopes separate and report the formatter baseline explicitly.
- S97: Privacy annotations must be enforced at raster composition, not only shown in a live overlay. Keep the unredacted source for Reset, but make every Copy/Save/Drag/Crop output call an opaque fill path and test the real App export boundary.
- S98: Session history is user-controlled memory, not a hidden persistence layer. An explicit Clear history action should remove every restore entry while preserving the current canonical image, report the change, and be unavailable during capture so the list cannot change mid-transaction.
- S99: Permission preflight is part of lifecycle ordering. Acquire the capture guard so concurrent requests remain serialized, but check known Screen Recording denial before hiding the editor; a recovery message is more useful when the editor stays visible and no needless restore transition runs.
- S100: macOS privacy settings can change while the editor is inactive. Recheck permission on window focus with a read-only Tauri command, ignore blur, skip during an active native operation, and epoch-guard the response so recovery is visible without creating a consent loop or clobbering newer user status.
- S101: A green packaged helper self-test is not physical UI evidence. Keep stable app/helper identity, permission/display-read checks, runtime-contract output, and one-process launch separate from toolbar/pointer/shortcut acceptance; a locked desktop or denied Accessibility controller is an explicit boundary that must be recorded rather than inferred around.
- S102: A package refresh must verify the exact installed bundle and the mounted canonical DMG, not only the build directory. Reinstalling the current arm64 package and comparing both artifacts closes provenance drift while keeping physical UI and public signing claims separate.
- S103: An independent UI harness must fail closed on control-plane prerequisites. Assert the exact installed process/signature and accessible control/menu surface, return a distinct blocked status for locked/Accessibility-denied sessions, and keep physical capture/export claims separate until the harness can drive them.
- S105: To test a reported non-clickable toolbar symptom, accessibility-name discovery is not enough; add representative reversible clicks. Keep the click phase after the prerequisite gate so a locked or Accessibility-denied run records `BLOCKED` rather than implying the controls were exercised.
- S106: Activation events can arrive in bursts, so a status epoch alone is not enough; it suppresses stale commits but still permits redundant native IPC. Add a single-flight ref around read-only focus refreshes and release it in `finally`, then hold the promise open in an App test to prove duplicate events collapse to one call.
- S107: A physical selector acceptance harness needs an explicit opt-in boundary because invoking `Capture area` is not non-destructive. Gate it on helper permission preflight, observe the exact native selector process, send Escape, and verify editor restoration; classify missing Accessibility, locked desktop, or Screen Recording as `BLOCKED`. In System Events, `process "shoteye"` resolves the executable while a bundle-identifier query can fail with `-1728`.
- S108: When a parent capture process passes TCC preflight but a bundled helper explicitly denies it, falling back to `screencapture` can recreate the consent prompt on every attempt. Treat explicit helper denial as a fail-closed permission mismatch with actionable recovery; reserve fallback for inconclusive probes or recoverable launch failures, and prove the distinction with dispatch tests.
- S109: Permission status is only useful when it describes the identity that will actually read pixels. Probe the bundled helper off the UI command thread, distinguish explicit mismatch from inconclusive execution, and keep the user-facing message exact enough to identify the installed app. Run frontend commands from `tauri-app`; a root-level `npm test` failure is command scope, not product evidence.
- S110: A status footer is part of recovery UX, not decorative chrome. If asynchronous permission/capture messages can be long, its layout row must grow and wrap; adding an explicit polite live region makes the same state visible to assistive technology. Verify the real App semantics separately from physical Accessibility automation, and record `-25211` as an environment block rather than a product result.
- S111: Finder drops are untrusted event payloads, not browser File objects. Validate the path list and extension at the edge, select one supported image deterministically, then reuse the existing guarded canonical importer so drag-and-drop cannot create a second image state or bypass export/history invariants.
- S112: Privacy annotations need both a visible editor affordance and a raster export guarantee. Pixelate can sample source colors in blocks, but `getImageData` may be unavailable; catch that boundary and fail closed to opaque black so Copy, Save, Drag, and Crop cannot export unmasked content. Test the real App export path and give canvas mocks the same `canvas` back-reference as production.
- S113: A privacy blur should be bounded and separable so large screenshot regions do not trigger quadratic work. Keep the selected source region isolated, preserve the existing export revision boundary, and fail closed to opaque black when pixel reads fail; a live clipped blur preview and a raster boundary test catch different classes of regressions.
- S114: Native menu structure is only useful when its callbacks stay on the current React action path. Record every supported editor tool in one menu model, route through a synchronous current-state dispatcher, and test an actual recorded callback; when the test matcher setup does not include `jest-dom`, assert the rendered class through the project's native matcher style rather than weakening the behavior check.
- S115: A documented keyboard shortcut can silently disappear when the toolbar and menu paths are tested independently. Add the shortcut to the shared pure mapper, route it through the existing guarded action, and exercise a real App key event so repeat capture inherits the same busy, preview, and status guarantees.
- S116: A working shortcut still needs discoverability at every command surface. Put the same accelerator on the native menu and visible toolbar control, expose `aria-keyshortcuts`, and test metadata without changing the accessible name so menu, keyboard, and toolbar remain one guarded action.
- S117: Shortcut metadata can drift even when every surface works today. Keep one canonical registration value and derive menu, display, and ARIA forms from it; a focused contract test makes future shortcut changes fail at the source instead of after packaging.
- S118: Power-user discoverability belongs on the control itself. Visible shortcut hints, tooltips, and ARIA metadata reduce the gap between native menus and toolbar usage; centralizing the values keeps the hints truthful without creating alternate action handlers.
- S119: Notarizing only the final DMG leaves the embedded app's ticket unverified and can make a strict release check fail. Submit/staple/validate the app archive before creating the DMG, then submit/staple/validate the DMG before refreshing the canonical download; a fake-`xcrun` ordering regression proves this without Apple credentials.
- S120: A permission probe must describe the executable that actually reads the pixels. When a bundled selector is the primary area-capture reader, a stale parent preflight must not mark area capture unavailable; use an explicit selector grant for that mode, preserve fail-closed denial/inconclusive paths, and keep system-capture modes on the parent grant.
- S121: A permission button can recreate a prompt loop even after capture itself is selector-aware. When the packaged pixel reader exists, inspect that identity first and keep the OS consent request behind an explicit unbundled-build boundary; status, request, and capture must share the same reader model.
- S122: A display-read probe is weaker than an output-boundary proof. Exercise the actual compositor and PNG writer with a small deterministic multi-display-shaped fixture, validate signature/dimensions/content, and run it against the installed app and mounted DMG while labeling it synthetic rather than physical acceptance.
- S135: A compositor self-test is necessary but not sufficient for a mirror report. Follow it with a real installed-package capture and inspect the copied PNG; the current `800×700` artifact is upright after removing the extra y-axis reflection.
- S137: Native Finder drag startup crosses three coordinate systems and an asynchronous file consumer. Capture the WebView pointer at pointer-down, convert it using the AppKit view's flipped state, build the synthetic event in window-base coordinates, and retain the staged URL until managed shutdown cleanup.
- S123: A ref-only exclusivity guard prevents overlap but gives the user no trustworthy progress signal. Store the native phase in React state, gate every competing native command, and clear it from `finally`; keep the Save dialog as an explicit editable phase so annotation changes made while the chooser is open are rendered into the selected destination.
- S124: Shortcut registration is a native transaction even when it is only one IPC call. Keep a single-flight registration guard, expose its state, preserve the last active shortcut on conflict, and translate platform-neutral accelerator syntax before showing the error; otherwise the UI can look ready while capture is temporarily unavailable or the user cannot tell which shortcut remains active.
- S125: A supported macOS launcher is part of permission correctness. `open -n` can deliberately create a second process from a different bundle path, making duplicate windows and TCC identity drift look like an app bug. Install and focus one architecture-specific bundle with `open -a`, archive stale generated apps recoverably at package time, fail closed if a stale executable is live, and guard the scripts with a no-`open -n` contract test.
- S127: A mounted DMG payload with the same bundle identifier is not an independent launch target while the installed app is alive. For exact package acceptance, stop only the installed test executable first, canonicalize `/var` symlinks when matching temporary paths, and terminate the mounted payload before detaching so a verifier cannot leave a resource-busy volume or leaked second process.
- S128: Core Graphics display images already have the correct visual orientation for this bitmap path; an extra y-axis reflection in the compositor makes the written PNG appear vertically mirrored. Assert the written top/bottom rows at the output boundary, and widen `UInt8` color comparisons before arithmetic so the regression fails cleanly instead of trapping.
- S129: A Tauri WKWebView can expose the native application menus to System Events while exposing only traffic-light buttons from the WebView's DOM. Treat that as a harness capability boundary: use the real native menu for packaged command/lifecycle acceptance, record the limitation, and keep it separate from physical toolbar pointer evidence. A HID drag plus the product's own Copy path can then prove selector-to-clipboard behavior without pretending to prove DOM button Accessibility.
- S130: System Events' `button of window` query is shallow. The ShotEye toolbar is accessible when the harness traverses `entire contents of window` below `AXWebArea`; a Pin toggle may be exposed as `AXCheckBox`. A shallow query can therefore produce a false "nothing is clickable" diagnosis even while the packaged toolbar controls are present and actionable.
- S131: To prove the reported capture action, exercise the actual installed toolbar control, then the real selector and product Copy path. A native-menu or helper self-test alone is too indirect; the bounded HID run produced a `600×500` PNG and confirmed selector exit and editor restoration.
- S132: A shortcut feature is only proven when it works outside ShotEye's focus. Record the custom binding through the packaged control, trigger it with another app frontmost, cancel the selector, and verify the reset binding independently; unit mapping tests alone cannot prove the native registration boundary.
- S138: Validate Save with bytes produced by the exact installed package, not only export unit tests. If the save panel or WebView is not fully exposed to Accessibility, use keyboard navigation and record reopen as smoke coverage rather than overstating pixel-equivalence.
- S139: A release verifier should fail before packaging claims are published when the signer is local-only. The explicit Developer ID rejection is useful evidence that the public-release gate is enforced, not evidence that notarization is complete.
- S140: Re-run the complete local verifier after acceptance artifacts exist. Keeping helper, package, DMG, and artifact checks in one report makes it clear which evidence is local and which release gates remain external.
- S141: Hardware-dependent acceptance must begin with an authoritative display inventory. If only one display is present, preserve the limitation; if Accessibility becomes inconsistent, do not convert a partially driven shortcut attempt into a pass.
- S142: A Carbon `RegisterEventHotKey` helper can report success in two processes for the same chord on macOS, so “reserved” does not mean “exclusive conflict owner.” Probe exclusivity with a second short-lived registration before testing product conflict; classify duplicate acceptance as `BLOCKED`, clean both processes, and never call the resulting ShotEye behavior a conflict.
- S142: Direct `AXUIElement` traversal is a more stable packaged control boundary than relying only on System Events' WebView projection. Keep a native-menu fallback and report the selected surface so missing WebView roles are not confused with a product failure.
- S143: Shortcut replacement is a transaction: register the candidate first, remove the old binding second, and roll back the candidate if old-binding removal fails. Extracting that boundary makes preservation/rollback testable without pretending a non-exclusive OS fixture is a real conflict.
- S144: A long-running packaged verifier must retain its execution session handle before polling. If the handle is lost, do not launch a second copy to observe it; terminate exact verifier processes, prove selector/ShotEye cleanup, and classify the missing terminal observation as BLOCKED.
- S146: Accessibility automation is an external process boundary. Wrap every AppleScript invocation in a bounded timeout, preserve the terminal report, and verify exact selector/process cleanup after cancellation; otherwise a hung controller can be mistaken for a capture defect or silently leave duplicate test state.
- S147: The strongest local capture proof follows the installed toolbar through the selector, a real HID drag, ShotEye's own Copy command, PNG structural validation, and one representative visual orientation check. Keep the resulting claim scoped to the tested primary display.
- S148: Physical desktop harnesses are exclusive consumers of the Accessibility/UI surface. Never run selector cancellation and shortcut-conflict acceptance concurrently; stop only the owned test controllers, verify selector cleanup, and rerun the affected path serially. Promote a manual physical proof into a checked-in bounded harness with artifact-level PNG validation before relying on it for release evidence.
- S149: A test artifact option is a write boundary. Canonicalize and constrain caller-supplied report/image locations to a project-owned evidence directory before replacing an earlier artifact, then rerun the real path to prove the guard did not weaken the acceptance.
- S151: Framework substitution is not an acceptance strategy when both layers terminate at the same native API. Inspect the resolved dependency implementation before proposing it as an alternate shortcut-conflict fixture.

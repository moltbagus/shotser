# ShotEye Lessons

- Do not treat a visible toolbar or a passing build as proof that the screenshot workflow works; packaged launch, capture, restore, Copy, and Save each need direct evidence.
- Do not use a mutable temp capture file as product state. Store validated image bytes in the app model and use files only at native adapter boundaries.
- When macOS permissions or ad-hoc signatures change, verify the exact installed `.app` path and bundle identity before asking the user to retest.
- Tool labels are not features. An editor tool is only complete when its image-space geometry is visible, cancelable, and present in the Copy/Save result.
- For Tauri lifecycle work, test the packaged ACL path, not just the Rust window API. `core:default` does not authorize frontend hide/show/focus calls.
- A native capture process can exit successfully without producing an image; treat a missing output file as cancellation/unavailability, never as a successful capture.
- Use Open/Paste as a deterministic, permission-independent acceptance path for editor/export behavior; do not let the desktop selector block verification of annotation and export correctness.
- Ad-hoc macOS signatures can invalidate or fail to retain Screen Recording access after each rebuilt binary. Expose a first-run recovery route, and treat Developer ID signing as the durable release solution.
- Preflight Core Graphics screen-capture access before spawning `screencapture`; a denied or stale TCC record must produce one clear in-app recovery state, not a macOS consent prompt on every capture attempt.
- Internal stack names and diagnostic controls are evidence tools, not product UI. Keep their seams for tests but do not expose them in the shipped editor.
- Native window chrome must have a single owner. Do not render duplicate traffic lights inside the WebView when the Tauri window already has a standard macOS titlebar.
- For packaged annotation acceptance, verify the user-visible status transition as well as the pixel position: Select → drag must report a move, and Undo must restore the prior annotation state without changing the annotation count.
- Crop rectangle geometry is a pure product boundary: cover conventional, reverse, and edge-clamped drags before relying on native Canvas behavior.
- A product rename must include the macOS bundle product name and window title, not only the rendered webview heading; otherwise the menu bar reveals the implementation-era name.
- A stable self-signed local identity can make local signing reproducible, but it is not a Developer ID certificate and cannot make a distributable or notarized public beta; verify TCC continuity on the exact packaged app before treating it as a permission fix.
- A certificate-signed Tauri package can pass `codesign --strict` yet still fail to boot its WebKit editor. In this app, a self-signed local certificate produced a blank window while the byte-equivalent ad-hoc control rendered normally; retain the known-good ad-hoc configuration until a real Apple Developer identity is available.
- A selected annotation is the prerequisite for showing resize handles. The packaged acceptance path must explicitly click the mark after switching to Select; simply changing tools correctly leaves handles hidden because no annotation is selected.
- For a bundled native helper, inspect the actual `Contents/Resources` tree after packaging and test the runtime lookup path. A valid Mach-O resource at the wrong relative path is an integration failure even when the app itself launches.
- During selector handoff, deactivation is not always cancellation: once a valid drag has committed, preserve the capture phase until the helper finishes. Use a cleanup guard for the private native output directory so every exit path removes it.
- When the product promise includes window capture, expose a distinct native mode and test its exact OS arguments; reusing fullscreen or area labels hides a real behavior mismatch even when the generic capture path compiles.
- Permission status should be observable before the first capture attempt, but the startup check must call only the non-prompting preflight API and leave the explicit consent action separate.
- A power-user Pin control needs an in-flight guard and failure rollback; rapid toggles or a missing window ACL must not leave a misleading “Pinned” label.
- Harden every clipboard staging path, not just screen-capture output: predictable filenames can be replaced or collide even when the canonical image state is otherwise Rust-owned.
- Format-aware Save needs byte-level tests that decode the generated file and compare dimensions; checking only the extension can ship a PNG with a `.jpg` suffix or a corrupt TIFF.
- Packaged keyboard acceptance must verify the observable state transition, not only that a key event was delivered: `Cmd+Z` should change annotation count/status and `Cmd+Shift+Z` should restore both.
- AppKit borderless selector cancellation needs an explicit key-capable `NSPanel` and a deactivation cleanup path; a `keyDown` implementation alone is insufficient.
- Keep native capture state transactional: remove stale output files before a run, but retain the prior Rust capture until the replacement passes PNG and dimension validation.
- For multi-monitor composition, test coordinate transforms independently from physical capture. Upper/lower display arrangements can pass a single-monitor smoke test while silently inverting output.
- Audit third-party Tauri plugins at the source boundary before adding them: an archive-specific file-promise plugin with an incorrect v2 command example and disabled default extractor is not a safe general-purpose PNG drag-out dependency.
- AppKit drag initiation is event-sensitive. Schedule the native call on the macOS main thread, require an active `NSApp.currentEvent` and key window, and return an actionable error when the IPC call no longer has a valid pointer event.
- A Finder drag needs longer-lived ownership than clipboard staging. Retain each private staged capture in managed state until shutdown so asynchronous Finder consumption cannot race temporary-file cleanup.
- The originating pointer event is not carried through Tauri IPC; native drag startup must create a fresh AppKit event on the main thread and use a visible drag image to make the session reliable.
- Background export preparation must be serialized with user-triggered Copy/Save and guarded by a revision token; otherwise a delayed older annotation render can become the drag payload.
- Keep legacy executable prototypes out of the root build path. A stale script that packages the old app can recreate duplicate-process and dead-click reports even when the supported Tauri bundle is healthy.
- Publish frontend shortcut readiness only after the listener registration promise resolves, and keep readiness plus pending requests under one lock to close the native startup race.
- Treat a cross-monitor composite as transactional: if one required display image is unavailable, fail the whole capture rather than accepting a valid-looking PNG with transparent gaps.
- Process smoke checks must match the executable field exactly (or an anchored product suffix), not search the entire `ps` row; otherwise the shell/awk command can report a duplicate process or hide a single-instance handoff.
- Diagnostic IPC acknowledgements are unsafe in a user-facing editor when they share the status channel with capture and permission results; keep tool selection local or use a dedicated command whose response cannot overwrite product status.
- Renaming a bundled executable requires a clean bundle replacement: in-place copy can retain the old binary, and Launch Services may continue starting it. Move the exact prior app to Trash, copy the new bundle, and verify both `CFBundleExecutable` and the live process path.
- Public packaging must fail closed: local ad-hoc/self-signed identities are useful for evaluation but cannot satisfy Developer ID, Gatekeeper, or notarization requirements. Validate the exact identity before invoking the release build.
- A parent Screen Recording grant does not automatically prove that a bundled helper has the same TCC access. Add a non-prompting helper probe before showing an overlay; on the reserved denial result, choose the system selector fallback without opening a second consent path.
- Treat a bundled selector as an optimization, not a hard dependency: platform-specific process-spawn failures can surface as `ErrorKind::Other`, so every helper exec failure should reach the tested system-selector fallback.
- Persisted global shortcuts can become invalid after another app claims the key or after a permissions/configuration change. Recover only at startup by clearing the rejected preference and showing the known active default; preserve the active shortcut when a user explicitly tries a conflicting replacement.
- Export actions are asynchronous and can outlive the React render that started them. A revision-checked helper plus latest-state refs is the smallest reliable boundary for preventing stale Copy, Save, or Drag payloads; test both one retry and perpetual instability.
- Keep package acceptance checks in one checked-in verifier and make physical UI claims separate. Bundle parity, code signing, helper preflight, and PNG structure are strong local evidence, but none is a substitute for dragging a real selector or dropping a file into Finder.
- Treat Copy, Save, and Drag as one native export lane. A revision token answers “which image?”, while an exclusive action guard answers “which operation owns the adapter right now?”; both are needed for deterministic power-user behavior.
- The capture adapter belongs in that same lane. A user can trigger capture from the toolbar or global shortcut while an export is pending, so separate “capture busy” and “export busy” flags are insufficient even when each flag is individually correct.
- Native menu callbacks should delegate through current action refs; capturing a React render's handler when the menu is installed can export stale image state after annotations or captures change.
- Multi-monitor geometry needs an executable self-test even when physical displays are unavailable. Reject uncovered logical slabs before creating the output context, and require a positive helper preflight before launching the bundled selector.
- Native capture must have a process-lifecycle budget. A helper timeout must kill/reap the child and release the frontend operation lane; falling back to another selector after a timeout can recreate the original freeze/duplicate-overlay symptom.
- Every asynchronous startup status producer needs an epoch captured before its await; otherwise a permission or menu response can replace the result of a later user action.
- Render prewarming and native persistence are different responsibilities. Keep prewarming pure and revision-scoped; only the exclusive user operation may call the Rust state-mutating export command.
- A package step that invokes Finder automation can hang without failing. Prefer deterministic `hdiutil` payload creation and verify the mounted DMG itself before treating packaging as complete.
- `CGRect.integral` hides the rounding policy at a display boundary. Use explicit floor-min/ceil-max bounds for both source crops and destination rectangles, then test fractional origins, seam columns, and vertical bands end to end.
- A compositor test can pass while the real display crop is inverted because it injects already-cropped images. Factor the crop transform and test top-row-first full-image data at both display extremes.
- Permission recovery is user-facing native work too: launch System Settings through the same owned-child deadline as capture so a stuck opener cannot strand the editor.
- A mixed-DPI compositor test that checks one center pixel can miss a seam shift or transparent edge. Use explicit RGBA/nearest-neighbor output and scan every synthetic output pixel for expected ownership and opaque coverage.
- Compositor self-tests should inject synthetic `CGImage` inputs and avoid `NSScreen`, TCC, or the AppKit run loop; this makes coordinate and scaling regressions runnable in package verification even without a second physical display.
- A failed default global-shortcut registration must not be a fatal Tauri setup error. Keep the value and registration state separate so startup can remain usable and the frontend can retry or record a replacement.
- Permission debugging must include the launch path: if the runner opens a build-tree bundle but settings and verifiers target `/Applications/ShotEye.app`, the operator can enable the right name and still test the wrong TCC identity. Canonicalize install, launch, and verification to one exact bundle path.
- Permission preflight alone is weak evidence for capture reliability. Exercise the real Core Graphics display-read boundary noninteractively in the exact packaged helper, then keep area-drag and multi-monitor claims separate.
- A permission prompt is a shared native resource across toolbar and menu entry points. Guard request and settings actions together, disable both controls while pending, and epoch-check terminal status so delayed TCC responses cannot overwrite a newer capture or import result.
- Package identity evidence must be deterministic: reject an unsigned source before installation and validate the exact architecture/version DMG rather than the first historical filename that happens to match.
- Audit canonical-image writers as a set: Open, Paste, and Crop must serialize with capture and export, not only with each other, because each can replace the Rust-owned image used by later Copy/Save.
- Treat child polling errors as lifecycle failures: `try_wait()` can return an I/O error before timeout, so kill/reap before propagating it and releasing the caller's operation lane.
- Test selector fallback as a policy matrix, not only as isolated predicates: denied and unknown probes, helper exit codes, spawn errors, and timeouts each have different user-visible consequences.
- S61: frontend capture lifecycle tests should assert event order and independent error channels; a successful native command is not enough if the editor is not restored and focused afterward.
- S62: test recovery calls independently; chaining `show()` and `setFocus()` in one `try` block can silently skip the second recovery action after the first native call fails.
- S63: keep structural capture signals separate from visual acceptance; check process exit, PNG signature, and dimensions first, then reject an all-black environment artifact as proof of UI pixels or pointer selection.
- S64: event-driven AppKit code still benefits from pure boundary tests; normalize drag coordinates once and run the same minimum-size rule for both preview and commit.
- S64 follow-up: reducer-style native interaction state makes reset semantics explicit; undersized mouse-up, Escape, and deactivation must all converge to idle before another drag is accepted.
- S65: user-visible Save is a durability boundary. A successful encoder call is not enough when the destination is written directly; same-directory atomic replacement preserves the prior file across partial-write failures.
- S66: acceptance scope must match the control plane. Process counts and logs can prove launch/single-instance health, while toolbar, clipboard, Save, and drag behavior require an Accessibility-capable UI harness or direct operator interaction.
- S67: release gates are evidence too. A fast, actionable preflight failure is safer than producing another unsigned package that users may mistake for a notarized release.
- S68: toolbar polish is a reliability affordance, not only visual styling. A shared minimum target and explicit focus ring improve discoverability while preserving the existing action boundary; package checks still cannot substitute for physical UI acceptance.
- S69: platform-dependent glyphs can make a correct toolbar look inconsistent or ambiguous. Stable inline vector icons improve recognition without changing the underlying action contract; verify the package separately from physical pointer acceptance.
- S70: unbounded clipboard helpers can recreate the original “nothing is clickable” symptom even when capture is healthy. Every native child in the user action lane needs a deadline, cleanup, and a terminal status that releases the shared guard.
- S71: user-controlled dialogs widen the stale-state window. Final export preparation belongs after destination selection, with a revision check immediately before native persistence; source ordering plus package verification is stronger evidence than a pre-dialog render test.
- S72: “one supported product” must include ignored artifacts, not only source directories. A stale app under `dist/` can recreate duplicate-launch reports even when the root runner is correct; archive it and enforce the layout at package time.
- S73: release invariants should be tested in both directions. Verify the supported package succeeds and a deliberately injected duplicate bundle fails closed, then clean the probe before handing off the workspace.
- S74: macOS can label a screen-only permission as `Screen & System Audio Recording`; explain the platform label explicitly while preserving a non-prompting screen preflight. Ad-hoc rebuilt bundles still lack durable TCC continuity, so Developer ID remains the release fix.
- S75: async UI work needs a synchronous invalidation boundary. A pure equality predicate plus current refs prevents delayed Crop results from committing after Reset/import/annotation edits; deferring crop persistence to the already-guarded export boundary also prevents stale native state. Add a controllable App-level promise harness next.
- S76: native event behavior deserves a separate evidence layer. Keep pure state tests, then exercise the actual AppKit view handlers with synthetic events so responder, coordinate conversion, callback count, and Escape cleanup are verified without requiring user permissions.
- S77: a separately executed native helper is part of the distributable trust boundary. Release packaging must validate its Developer ID authority and matching Team ID, not only the outer app's signature; evidence reports should record executable self-test exit codes rather than unconditional prose.
- S78: single-instance focus recovery can be destructive during a hidden capture. Make native capture activity observable to the activation callback and let the capture's RAII guard own the interval; duplicate launches must wait for normal completion restoration instead of revealing the editor mid-selection.
- S79: package verification must state its trust level. Local ad-hoc bundles can pass structural and strict-signature checks while still being unsuitable for distribution; an explicit release mode prevents false confidence and keeps the exact app/helper/DMG gates observable.
- S80: a keyboard shortcut can fail after a successful import without any native error because the DOM listener still owns the pre-import render's closure. Treat state-dependent preconditions as effect dependencies and verify the packaged build after the fix.
- S81: menu structure tests do not prove menu behavior. Audit the callback registry against toolbar/keyboard paths and test the shared dispatcher boundary; the next evidence gap is a packaged IPC contract, not another native-helper self-test.
- S82: status precedence must not discard successful work. When a capture result and restoration error coexist, preserve the image and report the recovery issue; when shortcut fallback registration fails, never claim the fallback is active.
- S83: A command-boundary failure can masquerade as a native lifecycle timeout. The runtime trace proved capture reached completion, but the report IPC used snake_case keys against Tauri's camelCase JavaScript mapping and was rejected before the handler body. Preserve the first missing boundary in traces, centralize payload construction, and prove the exact packaged app after fixing it.
- S84: Native restoration needs one owner and an observable result. A synchronous selector wait can leave a hidden WebView unable to resume, while duplicate React/Rust show/focus calls obscure the source of failure. Move blocking work off the UI command path, restore in Rust before returning, and make restore failures part of the status/contract.
- S85: Evidence artifacts need the same lifecycle discipline as product state. Reset per-run traces and log each restoration boundary so a future failure can be localized without confusing events from earlier retries.
- S86: When an asynchronous crop has a synchronous invalidation counter, extract the delayed resolver into a narrow helper used by production code. Controlled promises can then prove Reset and annotation edits invalidate stale work without adding a fragile native or UI dependency; keep component-level browser-state coverage separately labeled.
- S87: A reusable async helper is not the same as App-level evidence. Add an explicit DOM test runtime to the project, mock Tauri at the edge, drive real user-visible buttons and pointer events, and clean every mounted tree; otherwise later tests can fail from leaked UI rather than product behavior.
- S88: A component capture test can give false confidence if it clicks a disabled control or reuses a stale event listener. Exercise the pending guard through the current listener callback, clear mock history between tests, and assert both promise rejection and explicit cancellation recovery while keeping physical selector acceptance separate.
- S89: Accessible names and timing are part of component evidence. Query the real control name instead of an assumed label, reset dialog/native mocks per test, and control deferred image loading so annotated Copy, Save, and Drag assertions prove ordering rather than merely seeing a final status.

- S90: A stable local certificate is not enough if the package script hangs on keychain access or leaves the bundled helper ad-hoc signed. Use a bounded private-key probe, pass the identity to Tauri, sign nested executable resources before the outer app, and report matching app/helper authorities. Keep local signing separate from the Developer ID/Gatekeeper/notarization release gate.
- S91: A shared capture helper does not prove every toolbar mode reaches the correct native command. A compact parameterized `App` test matrix gives stronger routing evidence for Window, Full screen, and Repeat while preserving one lifecycle implementation and keeping physical macOS acceptance as an explicit external gate.
- S92: Any event queue crossing an async listener boundary needs a single readiness owner; otherwise an early shortcut can be lost without an error. Treat the canonical downloadable DMG as a build output invariant, not a manually maintained copy, and test the rejection path with an isolated mutated fixture.
- S93: Session history is safest when it records only successful canonical image results and remains immutable/bounded in memory. Restoring an earlier image is a source-state replacement, so reset annotations, crop drafts, and zoom in one guarded action; persistence should wait for an explicit privacy/storage decision.
- S94 audit correction: Adjacent line-range inspections can duplicate a boundary line and create a false double-call finding. Confirm suspected duplication with a symbol-scoped search and the smallest exact source range before proposing a code change.
- S95: Count-bounded base64 history is not memory-bounded. Apply both an entry cap and an encoded-payload budget, then test eviction with small synthetic strings so the safety property is deterministic.
- S96: Static-analysis tooling is part of evidence setup. Install `clippy`/`rustfmt` first, fix actionable Clippy warnings narrowly, and do not use a formatter pass to rewrite unrelated dirty native code merely to claim a green check.
- S97: A redaction tool that only changes SVG preview is unsafe. Model it as a normal source-coordinate annotation for editing, then enforce opaque black pixels in the shared raster compositor so Copy, Save, Drag, and Crop cannot bypass privacy masking.
- S98: A bounded session history still needs an explicit user privacy boundary. Clear the restore list through a single synchronous UI action, preserve the current image because it is active editor state rather than history, and disable the control while a native capture transaction is in flight.
- S99: A non-prompting permission guard can still produce a poor lifecycle if it runs after hide. Keep serialization before the check, then reject known denial before changing window visibility; reserve the full hide/restore path for an actually runnable capture or explicit lifecycle contract.
- S100: Permission state can change outside the app. Subscribe to native window activation and run a read-only refresh on focus, while skipping active native operations and guarding late results with the same status epoch used by user actions.
- S101: A green packaged helper self-test is not physical UI evidence. Keep stable app/helper identity, permission/display-read checks, runtime-contract output, and one-process launch separate from toolbar/pointer/shortcut acceptance; a locked desktop or denied Accessibility controller is an explicit boundary that must be recorded rather than inferred around.
- S102: A package refresh must verify the exact installed bundle and the mounted canonical DMG, not only the build directory. Reinstalling the current arm64 package and comparing both artifacts closes provenance drift while keeping physical UI and public signing claims separate.
- S103: An independent UI harness must fail closed on control-plane prerequisites. Assert the exact installed process/signature and accessible control/menu surface, return a distinct blocked status for locked/Accessibility-denied sessions, and keep physical capture/export claims separate until the harness can drive them.
- S105: To test a reported non-clickable toolbar symptom, accessibility-name discovery is not enough; add representative reversible clicks. Keep the click phase after the prerequisite gate so a locked or Accessibility-denied run records `BLOCKED` rather than implying the controls were exercised.
- S106: Activation events can arrive in bursts, so a status epoch alone is not enough; it suppresses stale commits but still permits redundant native IPC. Add a single-flight ref around read-only focus refreshes and release it in `finally`, then hold the promise open in an App test to prove duplicate events collapse to one call.
- S107: Keep physical capture lifecycle automation explicit and opt-in. The default Accessibility smoke should not trigger a selector; the opt-in path must gate permission, observe the real helper process, send Escape, and prove restoration. Prefer the executable process name for System Events targeting when bundle-identifier lookup returns `-1728`, and keep package verification responsible for bundle identity.
- S108: A permission fallback can be the source of the prompt loop. Differentiate `Some(false)` (explicit helper TCC denial) from `None` (inconclusive probe), stop the former before launching the system selector, and test both branches. After changing the dispatch contract, run Clippy because obsolete “positive probe” helpers can become dead code even when focused tests pass.
- S109: Diagnostic probes that spawn native helpers must be bounded and off the UI command thread. Keep parent and helper identity states explicit, test each message branch, and run package evidence after the probe is embedded. Scope frontend commands to `/Users/colbert1/shoteye/tauri-app`; a missing root-level npm script is an execution mistake to record and correct, not a failing app test.
- S110: Recovery text can be the longest content in a desktop editor. Use an auto-growing status row with safe wrapping and `role="status"`/`aria-live="polite"`; a fixed footer height can turn an actionable permission diagnosis into clipped or overlapping UI.
- S111: Tauri file-drop events carry native paths and can contain mixed or malformed values. Keep validation in a pure helper, handle only the first supported image, and route the result through the same exclusive import lane used by the file dialog; unit tests prove parsing while physical Finder acceptance remains separate.
- S112: A new canvas compositor can expose a fixture-only failure when tests omit properties available on real `CanvasRenderingContext2D` objects. Keep mocks faithful to the production contract (`context.canvas` included), and test both the normal pixel-read path and the privacy-safe fallback before packaging.
- S113: A blur implementation that samples every neighborhood naively will scale poorly on full-size captures. A separable sliding-window average keeps the cost bounded by region area and blur radius, while a clipped source image in the live SVG preview keeps the editor responsive and visually honest.
- S114: A native menu can look complete while silently missing the editor's newest tools. Keep the Tools inventory explicit and delegate each item through current React refs so menu commands share toolbar behavior; test the callback-to-active-tool transition, and use `className` assertions when the repository does not load `jest-dom` matchers.
- S115: Keep Repeat Last Capture a single lifecycle regardless of entry point. Mapping `⌘⇧R` in the shared editor dispatcher and testing the real App event prevents the keyboard path from drifting away from the guarded toolbar/menu action or creating duplicate native requests.
- S116: Shortcut discoverability is a product contract, not only a dispatcher contract. Keep the native menu accelerator, visible toolbar hint, tooltip, and `aria-keyshortcuts` derived from the same registration syntax, then test the UI metadata while preserving the existing single-flight action lane.
- S117: “Same shortcut” is not enough if it is encoded in multiple literals. Store the registration string once, derive platform/menu/ARIA forms, and test the conversion contract so accessibility labels and native accelerators cannot silently diverge.
- S118: A menu can advertise a shortcut while the toolbar still feels undiscoverable. Expose the same key on the primary toolbar controls, keep it `aria-hidden` so accessible names remain stable, and verify both the rendered metadata and the shared contract.
- S119: Release provenance has two notarization boundaries. The `.app` must be stapled and validated before DMG creation, and the DMG must be stapled and validated before its canonical copy is published; keep both operations behind a small injectable helper so order can be tested without Apple credentials.
- S120: Two executables can share one UI permission label while only one reads the display. Test the permission matrix `(parent, selector)` explicitly and derive the pre-hide gate from the capture mode's actual reader; this prevents a valid helper grant from being masked by an unrelated parent probe without reintroducing prompt loops.
- S121: The user-facing Permissions action needs the same identity reconciliation as the capture preflight. A selector-present build must not call the parent consent API for selector denial, timeout, or success; reserve that call for the unbundled fallback and test every matrix branch.
- S122: Packaged evidence should cross the helper's real output boundary. A small helper-generated PNG test catches compositor orientation, seams, encoding, and bundle-resource drift that Rust-injected runtime-contract pixels cannot; keep it separate from physical pointer and TCC claims.
- S123: A native-operation ref can serialize commands while the UI still appears clickable. Derive a visible phase from the same lifecycle, disable only the competing native lane, and test deferred completion/recovery; do not disable annotation tools during the user-controlled Save dialog because the destination is selected before export preparation.
- S124: A configurable shortcut needs an explicit active-versus-requested distinction. Treat registration as a guarded transaction, keep the old binding until the new one is accepted, make conflicts visible in familiar macOS notation, and gate global capture during the transition so a failed replacement cannot create a misleading inactive or overlapping state.
- S125: The launch command can recreate the duplicate-app symptom even when single-instance handling is correct. Keep package, install, and verification on the exact architecture-specific `/Applications/ShotEye.app` identity, use `open -a` to focus it, archive stale generated bundles at package time, refuse to move a live stale process, and assert the supported scripts never request `open -n`.
- S127: Same-identifier DMG verification must account for single-instance routing and macOS path aliases. Stop the exact installed test process before launching the mounted payload, compare canonical temporary paths, and clean up that exact payload before DMG detach; otherwise a valid launch test can fail as resource-busy and leave a second process behind.
- S128: Core Graphics display images already have the correct visual orientation for this bitmap path; an extra y-axis reflection in the compositor makes the written PNG appear vertically mirrored. Assert the written top/bottom rows at the output boundary, and widen `UInt8` color comparisons before arithmetic so the regression fails cleanly instead of trapping.
- S129: System Events may see ShotEye's native menus but not the React/WKWebView button roles. The packaged smoke harness should follow the accessible native menu path, document the WebView AX boundary, and avoid turning missing DOM roles into a false product failure. A real HID drag followed by ShotEye's own Copy Capture command provides a bounded selector-to-clipboard proof while keeping toolbar pointer acceptance separate.
- S130: A shallow System Events query sees only direct native window children. Traverse `entire contents` to reach the WebView's `AXWebArea` descendants, and classify Pin by its actual `AXCheckBox` role; otherwise a valid toolbar can be reported as missing.
- S131: The strongest available local capture proof follows the user-visible toolbar click through the bundled selector, a real HID drag, editor restoration, and the product's own Copy Capture command. Keep the result scoped to one display and do not infer shortcut, Finder-drop, secondary-display, or public-signing coverage.
- S132: Global-shortcut acceptance must cross the focus boundary. Test custom registration, invocation with another application frontmost, cancellation recovery, and reset-to-default; otherwise a green shortcut mapper test can still hide a native registration or stale-binding defect.
- S135: A compositor self-test is necessary but not sufficient for a mirror report. Follow it with a real installed-package capture and inspect the copied PNG; the current `800×700` artifact is upright after removing the extra y-axis reflection.
- S137: The Finder drag path crossed a delayed IPC boundary and an asynchronous file consumer. Capture the WebView pointer at pointer-down, convert it using the AppKit view's flipped state, build the synthetic event in window-base coordinates, and retain the staged URL until managed shutdown cleanup. The first two physical probes were invalid because one had no in-memory capture and one dropped onto an overlapping ShotEye window; the isolated Finder run passed.
- S138: Save dialogs are external UI boundaries. When their text fields are not exposed, keyboard navigation can still drive the flow; validate the exact output path, PNG header, dimensions, and bytes, and keep inaccessible reopen verification explicit.
- S139: Keep local evaluation and public release as separate states. A clean local signature is not a Developer ID identity; verify the release-mode rejection and preserve its output as a gate artifact.
- S140: A final local verifier should validate the exact installed identity and canonical DMG, not only the build-tree output. Preserve the report and label release trust separately from local correctness.
- S141: External UI acceptance has two separate prerequisites: the required hardware and stable assistive-control access. Record both independently so a one-display or inconsistent-AX session cannot produce a false world-class claim.
- S142: For shortcut-conflict automation, test the harness's ownership assumption first. The first Carbon fixture was not exclusive, and the app correctly accepted the same chord; the fix was a two-process exclusivity probe plus a fail-closed BLOCKED category, not weakening product conflict logic.
- S143: When an external registration API cannot provide exclusive conflict evidence, move the product guarantee to an injectable transaction seam and test its failure invariants directly while keeping the external acceptance blocked.
- S144: Preserve the subprocess session identifier returned by the execution tool for long-running UI acceptance. A missing handle is an observation problem, not permission to restart the same acceptance; clean exact processes first and record the missing evidence honestly.
- S146: Bounded controller calls convert an unobservable Accessibility hang into actionable evidence. Keep the timeout at the harness boundary and never restart a still-live acceptance without first proving the exact old controller is gone.
- S147: Do not infer physical capture correctness from a selector cancellation test. A real selection plus the product's own Copy output catches orientation and native handoff defects that unit tests and cancellation recovery cannot.
- S148: Treat packaged Accessibility controllers as mutually exclusive. Concurrent UI harnesses can contend for the same editor and invalidate both results even when neither product path is defective; serialize them, confirm exact helper cleanup, then preserve the physical PNG/report as the authoritative evidence.
- S149: Evidence harness flags can become destructive APIs. Resolve and constrain output directories before any artifact replacement; stable acceptance should not be able to overwrite an arbitrary user-selected path.
- S151: Trace the resolved shortcut dependency to the macOS API boundary before changing a fixture. Tauri/global-hotkey and the local fixture both use Carbon registration, so neither can prove the exclusivity Carbon itself does not enforce.
